# Edit users

User authorized autonomous implementation. Work in the current checkout so the running local app receives the feature.

**Goal:** System admins can open an edit modal from Member > Users and update display name, email, system role and active status. Password reset stays separate.

**Approach:** Reuse Ant Design modal/form and PATCH /users/:id. Extend the existing DTO/service with normalized unique email support; no database migration. A separate edit page would add navigation without helping this short form.

1. Add API integration tests covering normalized email persistence and login, duplicate/invalid email, blank name, permissions, missing users and self role/status protection. Run against a dedicated test database and confirm new cases fail.
2. Extend update DTO with trimmed email/name validation. Update service with email conflict handling including concurrent unique violations, atomic deactivation/token revocation, and actor checks. Preserve partial PATCH behavior.
3. Add a typed edit modal to MembersPage with prefilled fields, validation, saving state and error preservation. Refresh users/member caches and the current profile after saving. Disable own role/status fields.
4. Regenerate OpenAPI/client, run API tests and web build/tests, exercise edit/cancel/error/save through Playwright and restore changed sample data. Review the diff.

**Review focus:** Duplicate email must not partially update data; rejected self changes must leave the admin active; whitespace-only names must fail; cancel must not save; opening another user must reset fields.
